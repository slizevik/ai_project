# Домашнее задание №2. Данные и S3

**Цель:** построить воспроизводимый конвейер данных: сырые данные лежат в объектном хранилище в неизменном виде, а обработанный датасет собирается из них одной командой и выкладывается обратно в S3 с версией.

**Датасет:** CIFAR-10 — 60 000 цветных изображений 32×32, 10 классов, 50 000 в train и 10 000 в test. Вместо него можно взять CIFAR-100 (те же размеры, 100 классов и 20 надклассов). Этот датасет будет основой и для следующих домашек: в ДЗ №3 вы на нём проведёте эксперименты, в ДЗ №4 — сделаете сервис, который принимает картинку.

**Среда:** unix (macOS, Linux). Работаем в репозитории из ДЗ №1: все требования оттуда продолжают действовать — изменения только через pull request, `make check` проходит без ошибок.

---

## Блок 1. S3 в docker compose

1. Добавьте в проект `docker-compose.yml`, который поднимает локальное S3-совместимое хранилище. **Рекомендуется RustFS**; можно SeaweedFS или любое другое S3-совместимое хранилище.
   > ⚠️ **Не используйте MinIO.** Бесплатная версия MinIO больше не развивается, а её образы исчезли с Docker Hub — проект у проверяющего может просто не собраться.
2. Версия образа зафиксирована явно: тег конкретной версии, а не `latest`.
3. Данные хранилища лежат в именованном volume — после `docker compose down` и повторного `up` они не теряются.
4. Бакет создаётся автоматически при запуске: отдельным init-контейнером или скриптом. Руками в веб-интерфейсе ничего создавать не нужно.
5. У сервиса хранилища есть `healthcheck`, а зависящие от него контейнеры ждут его готовности.
6. Логин, пароль и адрес хранилища не захардкожены в коде:
   - код и `docker-compose.yml` берут их из переменных окружения;
   - в репозитории лежит `.env.example` с примером значений;
   - реальный `.env` — в `.gitignore`.

Этот `docker-compose.yml` вы будете расширять дальше: в ДЗ №3 в него добавится трекер экспериментов, в ДЗ №4 — сервис с моделью.

## Блок 2. Загрузка сырых данных в S3

Напишите скрипт загрузки, который:

1. скачивает архив CIFAR-10 с официального сайта (`https://www.cs.toronto.edu/~kriz/cifar.html`, версия для Python);
2. кладёт архив в S3 **как есть**, без распаковки и изменений, по пути вида `raw/cifar-10-python.tar.gz`.

Требования:

- **Идемпотентность:** повторный запуск ничего не скачивает и не загружает заново, если архив уже лежит в S3.
- **Сырые данные неизменяемы:** скрипт никогда не перезаписывает существующий объект в `raw/`.

## Блок 3. Конвейер обработки

Реализуйте конвейер, который запускается **одной командой** (например, `make data`), но состоит из **отдельных шагов**. Каждый шаг — отдельный модуль со своей CLI-командой, и его можно запустить отдельно.

### 3.1. Скачивание из S3

- Скачайте сырой архив из S3 в папку для сырых данных — ту, которую для этого предусматривает ваш шаблон проекта (обычно `data/raw/`).

### 3.2. Конвертация в безопасный формат

Python-версия CIFAR, которую вы скачали в блоке 2, хранится в формате `pickle` (на сайте есть ещё версии для MATLAB и бинарная, но мы работаем с Python-версией). Загрузка pickle-файла может выполнить произвольный код, поэтому его можно открывать только из проверенного источника.

Сконвертируйте данные в **папку с картинками и JSON-разметку**:

```
images/
    train_00000.png
    train_00001.png
    ...
    test_09999.png
annotations/
    train.json
    val.json      # появится после разбиения из 3.3
    test.json
```

- каждое изображение — отдельный PNG-файл в `images/`, имя файла — `image_id`;
- разметка — по одному JSON-файлу на выборку, в формате:

  ```json
  {
    "classes": ["airplane", "automobile", "bird", "..."],
    "images": [
      {
        "image_id": "train_00000",
        "file_name": "images/train_00000.png",
        "label": 6,
        "label_name": "frog",
        "sha256": "…"
      }
    ]
  }
  ```

- `sha256` — хеш байтов PNG-файла.

### 3.3. Фиксированное разбиение

- Выделите из исходного train валидационную выборку — например, 45 000 / 5 000.
- Разбиение **стратифицировано по классам**.
- Размер валидации и seed передаются аргументами или задаются в конфиге.
- Исходный test не меняется.
- Разбиение фиксируется самими файлами разметки: `train.json` и `val.json` вместе содержат все изображения исходного train, и каждое попадает ровно в один файл. Повторный запуск с тем же seed даёт ровно те же файлы.
- Картинки при разбиении не переносятся и не переименовываются: изображение, попавшее в валидацию, сохраняет `image_id` вида `train_…` — меняется только файл разметки, в котором оно упомянуто.

### 3.4. Статистики нормализации

- Посчитайте среднее и стандартное отклонение по каждому из трёх цветовых каналов.
- Считайте **только по train**, без валидации и теста.
- Сохраните результат в `stats.json`. Эти значения понадобятся при обучении в ДЗ №3 и в сервисе в ДЗ №4.

### 3.5. Выгрузка в S3 с версией

- Выгрузите результат в S3 по пути с версией, например:

  ```
  processed/cifar10/v1/
      images/              # 60 000 PNG-файлов
      annotations/
          train.json
          val.json
          test.json
      stats.json
      manifest.json
  ```

- `manifest.json` содержит:
  - число изображений в каждой выборке;
  - список файлов разметки и статистик с размерами и `sha256`;
  - параметры обработки (размер валидации, seed);
  - git-коммит, на котором выполнялась обработка.
- **Версии неизменяемы:** если `v1` уже существует, скрипт не перезаписывает её молча. Он либо завершается с понятной ошибкой, либо требует указать новую версию.

### Общие требования к коду

- Все параметры передаются через CLI-аргументы (`argparse`, `click` или `typer`) или через конфиг (YAML или JSON). Чтобы запустить скрипт, не нужно лезть в код.
- Код модульный: работа с S3, конвертация и разбиение — в разных модулях. Шаги можно запускать по отдельности.
- Структура проекта соответствует вашему шаблону; данные в git не коммитятся.
- Линтер и тайпчекер из ДЗ №1 проходят.

## Блок 4. Makefile и README

1. Добавьте цели в `Makefile` (названия можно выбрать свои, но смысл должен совпадать):
   - `make s3-up` — поднять хранилище;
   - `make ingest` — загрузить сырые данные в S3 (блок 2);
   - `make data` — запустить весь конвейер обработки (блок 3);
   - `make s3-down` — остановить хранилище.
2. В README добавьте раздел «Данные»:
   - как поднять хранилище и где посмотреть его содержимое;
   - какие команды запускать и в каком порядке;
   - что лежит в S3 после конвейера;
   - **краткая карточка датасета**: источник, размеры, классы, ваше разбиение, известные проблемы.

## Как вас будут проверять

1. Проверяющий клонирует репозиторий и поднимает окружение по README: `make setup`, затем `make s3-up`. Контейнеры поднимаются, бакет создаётся автоматически.
2. Проверяющий запускает `make ingest` и убеждается, что сырой архив лежит в S3 без изменений. Повторный `make ingest` не скачивает архив заново.
3. Проверяющий запускает `make data` и проверяет содержимое `processed/.../v1/` в S3: картинки в `images/`, файлы разметки в `annotations/`, `stats.json`, `manifest.json`.
4. Проверяющий запускает `make data` ещё раз и убеждается, что существующая версия не перезаписалась молча.
5. Проверяющий меняет параметр (например, seed или размер валидации) через CLI или конфиг, не трогая код, и собирает новую версию.
6. `make check` проходит без ошибок.

## Подсказки

- **boto3 и локальное S3.** Укажите `endpoint_url` с адресом вашего хранилища. Для локальных хранилищ обычно нужна адресация в стиле пути: `botocore.config.Config(s3={"addressing_style": "path"})`.
- **Ошибки при загрузке в S3-совместимые хранилища.** Свежие версии boto3 и AWS CLI по умолчанию добавляют к загрузке контрольные суммы, которые поддерживают не все S3-совместимые хранилища. Если видите ошибки вроде `InvalidRequest` или `SignatureDoesNotMatch` при загрузке, попробуйте переменные окружения `AWS_REQUEST_CHECKSUM_CALCULATION=when_required` и `AWS_RESPONSE_CHECKSUM_VALIDATION=when_required`.
- **Загрузка 60 000 файлов.** Если отправлять картинки в S3 по одной и последовательно, это займёт заметное время. Загружайте параллельно: например, через `concurrent.futures.ThreadPoolExecutor` — клиент boto3 можно использовать из нескольких потоков — или командой `aws s3 sync`.
- **Чтение pickle.** Файлы CIFAR читаются через `pickle.load(f, encoding="bytes")`. Пиксели лежат в массиве формы `(N, 3072)`: сначала 1024 значения красного канала, потом зелёного, потом синего. Чтобы получить изображения, сделайте `reshape(N, 3, 32, 32)`, а затем `transpose(0, 2, 3, 1)`.
- **Как посмотреть содержимое S3:** AWS CLI или `s3cmd` с указанием `--endpoint-url`, `rclone`, Cyberduck или веб-консоль вашего хранилища (у RustFS она есть).
- **Скачивание через torchvision.** Архив удобно скачать через `torchvision.datasets.CIFAR10(root=..., download=True)`: он скачает официальный `cifar-10-python.tar.gz` в папку `root` и распакует его рядом. В S3 кладётся именно этот архив `.tar.gz`, как есть.
- **Проверьте себя.** Перед сдачей удалите volume хранилища и локальную папку `data/`, затем пройдите весь сценарий по README с нуля.
